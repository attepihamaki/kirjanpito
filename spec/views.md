# App structure: shell, ledger, entry dialog and the main views

Part of the project specification. `CLAUDE.md` is the index and holds the conventions; section numbers are the same in every file, and code comments cite them as §N.

## 8. App structure and features

### 8.1 States and routes

- An **open/closed** flag: whether a bookkeeping is open. It is persisted. On load, if it isn't stored, it is true when entries exist.
- When **no bookkeeping is open**, every route shows the **landing page**.
- Views: landing, overview, ledger, VAT return, income statement, summary, calendar, settings. The prototype used Finnish hash routes (`etusivu`, `kirjanpito`, `alv`, `tulos`, `yhteenveto`, `asetukset`); the real app uses **English** Next.js routes — see §11b. Only the visible labels are translated.
- The app logo / brand links to the landing page.
- Persisted UI preferences: language, theme, selected year, last amount mode and type used in the entry dialog, rows per page for each table, and whether the sidebar is collapsed. Language and theme each have their own localStorage key; the rest live with the bookkeeping (§12).

### 8.2 Shell (sidebar + top bar)

The layout follows the sibling project FormBox (`../formbox`): a sidebar that
holds the brand and the navigation, and a top bar across the content area for
the open file and the user's preferences. **The top bar is the same at every
width**, so no control exists twice; below 900 px the sidebar becomes a sheet
instead of the app growing a second header. The earlier split — a desktop
sidebar plus a separate mobile top bar with its own copies of everything and a
row of nav tabs — is gone.

- **Sidebar** (`components/app/app-sidebar.tsx`, shadcn `Sidebar`,
  `collapsible="icon"`), top to bottom:
  - Brand: a "K" mark, "Kirjanpito", and the subtitle "Yhdenkertainen kirjanpito" — shortened from the prototype's "Toiminimen yhdenkertainen kirjanpito", which could not fit the button without truncating. The two lines need `leading-tight`: at the default leading they are 36 px and the `size="lg"` button's content box is 32. Links to the landing page.
  - Navigation with icons: Yleiskatsaus, Kirjanpito, ALV-laskelma, Tuloslaskelma, Yhteenveto, Kalenteri, Asetukset.
  - **Nothing below the navigation.** The sidebar is the brand and the seven views; the §1 disclaimer lives on the landing page and in the report notes, and the brand row is the route back to the landing page and its FAQ.
  - **15 rem wide**, one step under shadcn's 16 rem, which the six short labels do not need. `app-skeleton.tsx` draws the same width, so nothing shifts on rehydrate. The mobile sheet keeps its own 18 rem: it is an overlay on a phone, not a column beside the content.
  - ≥ 900 px it collapses to a 3 rem icon rail; below 900 px it is a sheet, and tapping a link closes it. **Everything in it is a menu row**, so collapsing loses only the words — there is nothing here that needs a second rendering to survive the rail.
  - The expanded / collapsed state is `sidebarOpen` in the store (§12), **not** shadcn's `sidebar_state` cookie: nothing is server-rendered, so a cookie could never be read back. `SidebarProvider` writes no cookie at all, and the app always passes it `open` and `onOpenChange`.
- **Top bar** (`components/app/app-topbar.tsx`), laid out like FormBox's `AppHeader`: `h-14`, `gap-2`, `px-4 lg:px-6`, sticky, and **no rule below it** — the sidebar's border already separates the chrome from the page, and a second line only boxed the content in. It holds only what is the same on every view: a panel icon on the left that collapses the sidebar (≥ 900 px) or opens it as a sheet (< 900 px), and, pushed right, the theme toggle, the language picker and the file menu. The panel icon is hand-rolled rather than shadcn's `SidebarTrigger`, which hard-codes an English screen-reader label.
  - **Every control in the bar is 36 px tall** — `size="icon"` buttons and the default `Select` trigger — so the row reads as one line rather than three sizes. Match that when adding anything.
- **File menu** (`components/app/file-menu.tsx`) — the open file and everything that acts on it, as one `Popover` at the right-hand end of the top bar:
  - The trigger is a `ghost` `size="icon"` button at the right-hand end of the bar, after the language picker, so the file reads as app chrome rather than as the one loud control in it. Its icon is lucide's `book-bookmark`, and the **amber status dot rides the icon's top-right corner the way an unread badge does**, only while there are unsaved changes. With no file name on the bar, the dot is the only always-visible sign of unsaved work. A saved book shows no dot on the icon. The green dot stays in the popup's status line. Nothing in the button is visible text, so the `aria-label` is `"{name}, {status}"` and the `title` is the file name. While a file is being read or written the icon is a spinner (§7.2, §7.5).
  - The popup, top to bottom: the file name and the status line (amber "Tallentamattomia muutoksia" / green "Tallennettu"); "Tilikausi" and a year selector, offering the years found in the data plus the current year and the selected year; and the actions as full-width rows with their icons on one line — "Avaa tiedosto", "Tallenna", "Lataa tiedosto", "Tarkista kirjanpito" (§8.23), "Tarkastuspaketti" (§8.25), "Sulje tiedosto".
  - **Three of the five rows carry a shortcut**, as a `<kbd>` key cap: muted text, recessed to `--background` rather than filled with `--muted`, which is what the row itself turns on hover. `hooks/use-app-shortcuts.ts` owns the one listener, and `useShortcut` in `use-save-book.ts` writes each combination both ways — `⇧⌘S` or `Ctrl+Shift+S` for the cap, `Meta+Shift+S` or `Control+Shift+S` for the row's `aria-keyshortcuts`.

    | row | shortcut | why |
    | --- | --- | --- |
    | Avaa tiedosto | `Ctrl`/`⌘`+`O` | universal, and a page is allowed to cancel it |
    | Tallenna | `Ctrl`/`⌘`+`S` | only bound where the browser can write to a file (§7.5); elsewhere it stays the browser's own |
    | Lataa tiedosto | `Ctrl`/`⌘`+`Shift`+`S` | reads as "save as", which is what a downloaded copy is |
    | Tarkista kirjanpito | **none** | opens a report, so it needs no key |
    | Sulje tiedosto | **none** | `Ctrl`/`⌘`+`W` is one of the few combinations a browser will not hand to a page, so binding it would close the tab instead |
    | (no row) | `Ctrl`/`⌘`+`Z`, `Ctrl`/`⌘`+`Shift`+`Z`, `Ctrl`+`Y` | undo and redo of changes to the entries and categories (§8.20); no menu row |

  - **`N` opens a new entry**, from the same listener, and "Uusi tosite" says so in its `title` and `aria-keyshortcuts` (`NewEntryButton`). `Ctrl`/`⌘`+`N` belongs to the browser, so this key has no modifier. It stays out of the way of typing: it does nothing in a field or a list that jumps by letter, behind a popover or a confirmation, or when held down.

  - **The key cap is `aria-hidden`, and the combination travels in `aria-keyshortcuts`.** Accessible names concatenate with no separator, so a cap inside the row would have it announced as "TallennaCtrl+S".
  - **No shortcut fires while a dialog is open**, or during an import or a save, or with no bookkeeping open. Every one of them replaces or rewrites the whole bookkeeping, and the entry being typed into a dialog is not in the book yet. `test/app-shortcuts.test.tsx` covers each refusal, and that the browser keeps its own default in those cases.
  - **Every row is a `ghost` button, with no highlighted one.** They are menu items, and a filled row among them would read as the only real action. The dot and the status line are what say there is unsaved work; a second signal competing with them only makes the popup louder.
  - **"Tallenna" is absent, not disabled, where the browser cannot write to a file.** A permanent dead control in front of every Firefox, Safari and phone user is worse than three rows that all work.
  - **The download is named after what it does, not after "Tallenna".** "Lataa kopio" would read as a copy of an original, which is wrong wherever the download is the only way to keep the work — and one label for one action beats a row that renames itself per browser. It also puts the row in line with "Avaa tiedosto" and "Sulje tiedosto". The dialog it opens is titled "Lataa kirjanpito".
  - **A linked file shows when it was last written** under the status line (`SavedAtNote`): "Tiedosto päivitetty klo 14.32", or with the date for an earlier day. It is the file's own modification time (`savedAt`), so after opening it says when the file was last changed, and after a save when this app wrote it. It is how a user tells whether the file on disk is current once a save has failed or autosave has paused. A downloaded copy has no linked file to date, so the line is absent.
  - The status words are about saving, not exporting, so one wording covers both ways of keeping the work. Which file is current is `dirty`'s job (§7.5).
  - The year belongs in here because it is read out of the file: this popup is the one place that answers "which bookkeeping, which year, and is it saved".
  - Every action closes the popup first — it hands over to a dialog, a picker, or empties the bookkeeping.
  - `components/app/file-status.tsx` holds the one wording of the save status: `useFileStatusText` for the trigger's accessible name, `StatusDot` for the dot alone (the trigger's badge, while the book is dirty), `FileStatus` for the dot with its label (the popup's status line).
- **Theme toggle:** one ghost button with a sun / moon icon that flips light ↔ dark, as in FormBox. There is no "system" control — next-themes still has `defaultTheme="system"`, so an untouched browser follows the OS; it simply cannot be chosen back. Both icons are always in the markup and CSS picks one off the `.dark` class, so the prerendered HTML is already right.
- **Language picker:** a `LanguagesIcon` button opening a checked list of Suomi / English (endonyms, so each option reads the same either way). Language stays a stored preference, never a route (§11b).
- **Drag and drop anywhere:**
  - Dropping a CSV or ZIP opens it. A full-screen overlay says "Pudota CSV- tai ZIP-tiedosto avataksesi sen".
  - While the entry dialog is open, dropped images and PDFs are attached to it instead, and the dialog gets a dashed outline.
  - Dropping media while no dialog is open starts a new entry with the files attached. A PDF among them pre-fills the form (§8.5).
- **Reading a file shows progress, but only once it is slow** (§7.2). `importing` in the store is raised for the whole of `openFile`, and `hooks/use-delayed-flag.ts` turns it into a visible state **after `BUSY_DELAY_MS` (400 ms)**: the file menu's trigger icon and its "Avaa tiedosto" row become spinners, "Lataa tiedosto" is disabled, and `components/app/import-overlay.tsx` covers the page with "Avataan tiedostoa…". A plain CSV opens in a few milliseconds and never reaches the delay, so nothing flickers; a ZIP of receipts does, and used to leave the UI silent for seconds. The overlay is **blocking**, unlike the drop overlay — the import is about to replace the whole bookkeeping. Both the app and the landing page render it, because a file can be picked from either and the drop overlay vanishes the instant the file lands. `importing` also guards re-entry: a second file dropped mid-import is ignored rather than interleaving two `replaceBook` calls.

### 8.3 Landing page

A full-width page with no sidebar. It has its own nav: logo, FI/EN, theme, and "Avaa tiedosto" (or "Avaa kirjanpito" when a bookkeeping is open). Sections:

1. **Hero.**
   - Headline "Toiminimen kirjanpito, joka mahtuu yhteen tiedostoon." and a lead paragraph.
   - Calls to action:
     - Closed state: "Aloita uusi kirjanpito" and "Avaa tiedosto", plus a dashed drop zone ("Pudota CSV- tai ZIP-tiedosto tähän…"). A file can be dropped anywhere on the page, with the same overlay as in the app (`useFileDrop`), and anything but a CSV or ZIP gets a toast.
     - Open state: "Jatka kirjanpitoa" (to the overview) and "Avaa tiedosto", with a meta line showing the file name, the number of entries and the unsaved-changes status.
   - Visual: two overlapping, slightly rotated paper receipts on a soft accent panel. One is an expense receipt, the other the October VAT calculation ending in "Maksettava 617,18 €". On small screens only the VAT receipt is shown.
2. **"Tositteesta veroilmoitukseen neljässä vaiheessa".** Four numbered steps: open or start, record receipts (including attaching), check the figures, export (a ZIP organised by year and month).
3. **"Mitä kirjanpito laskee puolestasi".** Three cards: VAT (with rate chips), income statement (a mini statement), and monthly summary (a mini bar chart).
4. **"Ei tiliä, ei tietokantaa".** A privacy explanation next to a CSV sample block.
5. **"Kysyttyä".** An accordion with five questions: who it's for, whether it files returns, moving over from Excel (lists the columns; `receipts` is optional), what happens when the browser is closed, and what happens to the books when the business closes (below).
6. A closing call to action, "Aloita tämän kuun tositteista.", and a footer with the disclaimer "Laskelmat eivät ole vero- tai kirjanpitoneuvontaa." and a link to the privacy statement at `/privacy` ("Tietosuoja"). The footer is shared with the 404 and the statement itself (`SiteFooter`).

   **The privacy statement** (`components/privacy-page.tsx`) is a public static page like the landing, in the stored language, and is in the sitemap. It says who holds the data (the user alone; the author receives and keeps nothing; GitHub Pages only serves the files), what is stored where (localStorage keys, the three IndexedDB databases, the saved ZIP, and what is not used), that the CSP holds the page to its own origin, what encryption and the integrity seal do and do not protect (§7.8, §7.9), and how to clear the data. When storage (§12) or the CSP (§11b) changes, change this text in `lib/i18n/dict/landing.ts` (`privacy.*`) with it.

- "Aloita uusi kirjanpito" opens the empty overview and sets the year to the current year. If there are unsaved changes, it asks first.
- **It then opens the setup dialog** (`components/settings/setup-dialog.tsx`, `DialogState` kind `setup`), which asks for every book-level setting a bookkeeping starts with rather than deciding them silently: the business's name and ID (an ID that fails its check digit keeps the dialog open, §8.10), the export language (§7.1, seeded from the UI language), the trader type, the VAT period, the start month, and autosave where a file can be written at all. The getting-started checklist of §8.15 follows it on the overview. The controls are the ones Asetukset, Yleiset exports — `ExportLanguageToggle`, `VatPeriodToggle`, `BookStartSelects`, `AutosaveCheckbox` — not copies of them (§11). "Ohita" closes with the defaults; everything it asks lives on Asetukset, so it is never a dead end. `startBook` applies all four at once and leaves `dirty` false, since a bookkeeping nobody has typed into has nothing unsaved. The dialog is **not** shown when a file is opened: a file brings its own `settings.json`. Its host is in `AppShell`, which the route it navigates to mounts. `test/setup-dialog.test.tsx` covers it.

### 8.4 Ledger (Kirjanpito)

- Header: "Kirjanpito", the period ("Koko vuosi 2026" or "Lokakuu 2026"), and a primary "Uusi tosite" button.
- **Month chips:** Kaikki plus Tammi…Joulu, with entry counts. Empty months are greyed. The selected chip is filled in the primary colour. Each chip is shaped exactly like a default `Button` — **36 px tall** and the button radius (§11) — so the chip row and the toolbar below it read as one scale and one shape.
- **Totals cards** (§6.2): three cards side by side, each a bare `Panel`, stacking to one column under 640 px. One bar with dividers made the three figures read as a single row of a table; they are three separate answers.
- **Toolbar:** four controls of the same shape, left to right, and nothing pushed to the right-hand end. It is **hidden, together with the table, on a period that holds no entries at all** — the page then shows "Ei tositteita: Lokakuu 2026." A row of controls that cannot change the result reads as if the filters were what emptied the page. The filters keep their values while hidden and come back with the next period that has rows.
  - Search over description and category, an exact voucher number, and the **text of PDF receipts**. A PDF is read once (`extractPdfText`), by `useReceiptText` after a receipt reaches an entry and after an import, and its text is kept lower-cased in IndexedDB (`bookkeeping-receipt-text`, keyed by attachment id, cut to 100 000 characters). The index is a cache: it is not written to the file, it is dropped with the receipt in the sweep (§7.4), and a new browser rebuilds it in the background, so a search covers the receipts read so far. A scanned PDF has no text and stores "". An entry found only through a receipt shows an "In receipt" pill (`receiptOnlyHits`). The field is a **fixed 20 rem box**, not one that grows into the row: the queries are a word or two, and a field stretched across the toolbar reads as the page's main control.
  - **A search also reports where else it matches.** Under the toolbar, "Osumia myös muualla:" lists the other years with a match as buttons, "2025 (2)", newest first (`searchHitsElsewhere` in `stores/selectors.ts`). With one month on screen the selected year is listed too, for its other months. A button opens that whole year, keeps the search and clears the other filters, so the count is what the user then sees. The list stays out of the way until there is a search, and the table and totals remain one year's, since voucher numbers and totals only mean something within a year.
  - A type filter (Kaikki tyypit / Tulot / Kulut) as a **select**, like the category filter beside it. A segmented control would be the one control here shaped unlike the others, and it grows with the language. `EntryTypeToggle` (§8.5, §8.10) stays segmented because it is a form field, not a filter.
  - A category filter, listing only the categories used in the period.
  - "Tarkistettavat": Kaikki tositteet / Avoimet (entries not yet paid, §6.3; not a check, so it has no warning row) / Ilman liitettä / Verokanta ei vastaa päivää / Päivä tulevaisuudessa / Kotimaan myynti ilman ALV:tä / Poikkeuksellisen suuri summa / Mahdollinen kaksoistosite / ALV ei vähennettävää / Käteismaksu kirjattu myöhässä (`ledgerCheck`, §8.5). `lib/domain/entry-checks.ts` decides each one, for this filter and the overview's checklist alike, and it is given the whole selected year, so a month on screen does not change what stands out.
    - An entry counts as having a receipt only when a file is available; one listed in the CSV but missing from the ZIP does not. Every line is checked, calculated ones included, since their calculators attach a memo voucher (§8.8).
    - A rate mismatch is `rateMismatch` (§5).
    - A future date is any date after today.
    - A domestic sale without VAT is a line 300 `domestic` sale at 0 %, flagged only in a year that also has domestic sales with VAT, since a business that is not VAT registered sells everything at 0 %.
    - A large amount is a gross amount over ten times the median of that year's income, or expenses, given at least five of them, and never under 1 000 €. It is meant to catch a misplaced decimal comma.
    - A possible duplicate shares its date, side and gross amount with another entry, or a stored receipt file (same name, type and size). Both of a pair are flagged. Entries with the same `split` value are parts of one receipt and never a pair, in the filter and in the dialog's two hints. The category is not compared, since the same receipt entered twice can land in two categories.
    - Private use without VAT is a 0 % entry on line 314 in a year where that line adds up to more than 850 €, the free part for a natural person (AVL 21 §). Line 313 is not checked, since a car's VAT depends on how much of it was deducted. The entry dialog explains the rule under the category on 313 to 315.
    - Small purchase booked as an asset is a purchase of machinery and equipment whose net amount is at most `smallPurchaseItem` (1 200 €), in date order while the year's flagged purchases stay within `smallPurchaseYear` (3 600 €). Vero lets such a cost be deducted at once. Credit notes (`reverses`) are left out.
    - Large purchase booked as an expense is a line 344 "other" expense above `smallPurchaseItem`, net. Equipment over the limit is depreciated unless its useful life is 3 years or less, which the app cannot know, so this is a hint only.
    - VAT not deductible is an expense with VAT on entertainment (341) or a non-deductible line (365–367), `AccountLine.noVatDeduction`. VAT on entertainment cannot be deducted (AVL 114 § 1 mom. 3 kohta, checked in Vero's guide "Markkinointi- ja edustustilaisuudet arvonlisäverotuksessa"), and a cost that is not deductible for income tax is usually not for the taxable business either. Such a cost is booked at its gross amount with 0 % VAT, so the tax stays part of the cost; with a rate it would count as purchase VAT.
    - The overview's checklist sets this filter when it sends the user here.
  - "Tyhjennä suodattimet" when any filter is active.
- **Table columns:** a selection checkbox and Nro (the voucher number), both hidden under 560 px, then Pvm, Tyyppi, Kuvaus, Luokka, Veroton, ALV (amount, with the rate small below), Verollinen (bold, with "−" for expenses), and actions.
  - Every column is sortable, with ↑/↓ shown on the active column and ⇅ on the others. Sorting by gross uses signed values, and sorting by type puts income first.
  - **A header cycles through three states: ascending, descending, then no column chosen** (⇅ everywhere), so every sort can be undone. The third state is `ledgerSort: null` / `catSort: null`, **not the default order spelled out**: the column that order follows — Pvm here, Tili in the categories table — would otherwise be stuck between its two directions, because "back to the default" *is* that column ascending. With null it reaches ⇅ like every other column. The rows then take `LEDGER_SORT_DEFAULT` / `CAT_SORT_DEFAULT` from `stores/book-store.ts`, read where the list is built rather than where the header is clicked, and `nextSort` is the one implementation of the cycle.
  - A first click is always ascending, including on Pvm, where the rows are in that order already and only the icon moves.
  - Tyyppi is a `Pill` in the income or expense tone — the same badge as the categories table (§8.10), so the two tables read alike.
  - The description cell shows a **paperclip button** (with a count if there are several receipts) that opens the viewer.
  - Row actions: **edit (pencil)**, **copy as new**, and delete. Clicking or pressing Enter on a row also edits it.
  - **Two cells edit in place.** The description cell has a pencil button, shown on hover and on focus, that turns the text into an input: `Enter` or leaving the field saves, `Escape` cancels (`renameEntry` in `bulk-commands.ts`). The category cell is a select with the bulk bar's choices (`categoriesToMoveTo`) plus the row's own, so an EU purchase offers only EU purchases (`recategorizeEntries`). Both refuse a locked voucher (§8.11) and the category change asks about a filed period like the bulk action does. A rename moves the voucher's monthly template with it (§8.5), and both can be undone from the toast for 10 seconds. Date, amount and VAT stay in the dialog, since they move voucher numbers, the locks and the amount mode.
  - Responsive: the category column is hidden under 1240 px, and with it the inline category select. Under 560 px, the type, net, VAT and actions columns are hidden (tap the row to edit); the signed gross is what still tells income from expense there.
- **Bulk actions.** Ticking rows, or the header box for the whole page, shows a bar above the table (`components/ledger/bulk-bar.tsx`) with the count, "Vaihda luokka" and "Poista valitut".
  - The category list offers the enabled categories of the selected side, EU purchases only for EU purchases (§6.9). A mix of income and expenses, or of EU purchases and other costs, cannot share a category, so the bar says so instead of offering one. Each entry keeps its own VAT rate and its voucher number.
  - Both go through `lib/commands/bulk-commands.ts`: the delete asks first, both refuse an entry in a locked period (§8.11), and both can be undone from the toast for 10 seconds.
  - The selection belongs to the period and filters it was made under. Changing either starts over, so the bar never acts on rows that are no longer listed. It is component state, not stored.
- **Pagination:** the row count ("16 tositetta") at the left-hand end, and at the right "Rivejä sivulla" with a 10/25/50/100 select (default 10), "Sivu 1 / 2", and first / previous / next / last icon buttons. The strip reads as "what you are looking at" / "how to move through it", which is why the count lives here rather than in the toolbar. The page resets to 1 when filters, sorting or the month change. It sits **inside the table's surface**, as the categories table places it (§8.10) — `ledger-table.tsx` renders the table alone and the view composes the `Surface` around both. `TablePagination` owns that strip, its padding and the rule above it: the table body drops the last row's own bottom border, which in a table that ends its surface would land on the surface's edge. **It is always shown**, even on a single page: the rows-per-page select is how the page length is set, so hiding the row until the list outgrows that length would hide the only control that changes it.
- **Empty state** (open but no entries): "Ei vielä tositteita" with "Uusi tosite" and "Avaa tiedosto".
- **Empty state on the other views.** Päiväkirja, Pääkirja, ALV, Tuloslaskelma, Yhteenveto and Poistot show `NoEntriesState` (`components/common/no-entries-state.tsx`) when the selected year has no entries: "Ei tositteita vuonna {y}", one line naming the report, and the "Uusi tosite" and bank import buttons. A year marked as filed keeps its Tuloslaskelma. Toistuvat tositteet and Kalenteri offer "Uusi tosite" when empty, and Säännöt points at the form above the list.
- **Päiväkirja, Pääkirja and Tililuettelo.** The view has four tabs (`LedgerTabs`, routes `LEDGER_ROUTES` in `lib/site.ts`): Tositteet at `/app/ledger`, Päiväkirja at `/app/ledger/journal`, Pääkirja at `/app/ledger/accounts` and Tililuettelo at `/app/ledger/chart`. The Accounting Act asks that entries can be viewed "aikajärjestyksessä ja asiajärjestyksessä" (KPL 2:4, checked on Finlex), and these two are that, for the selected year (`lib/domain/books.ts`, `components/ledger/books-view.tsx`).
  - The journal lists the year by month, in date and then voucher order, with the account number, expenses as negative, and income and expense totals.
  - The general ledger lists the same entries by account in chart-of-accounts order (§5), only accounts that have entries, each with its total. A category is shown under the description unless it has the account's own name.
  - **The general ledger ends with a reconciliation to the income statement** (`ledgerReconciliation`), because the books go by the entry's date and the statement and Form 5 by the payment year (§6.3). KPL 2:6 asks that a return can be traced to its entries and back. Per statement line an entry crosses: the ledger total, minus what was paid in another year or is open, plus what is dated in another year and paid in this one, equals the line on the statement in full. The entries that move are listed under it. The section shows only when one does, and off-statement lines are left out. `books.test.ts` checks that every line reaches the income statement's own figure.
  - The account list (KPL 2:2, `accountList`) names each account with an enabled category or an entry that year and what it holds, followed by the list of books and material of KPL 2:7a. The Act keeps both for 10 years with the books. A note under them says what KPL 2:10 asks when the business closes: the same retention, and the closure notice names who keeps the material and where. For a sole trader that notice is form Y6 in YTJ, whose field "Kirjanpitoaineiston säilyttäjän nimi" cites 2:10 (YTJ 1006, 1.2026). The landing FAQ says the same.
  - All three are printable sheets on the `--sheet` surface with a "Tulosta" button, like the income statement (§8.8), and end with the retention rule of KPL 2:10, with the year's own dates: the books for 10 years from the end of the financial year, the vouchers for 6 years from the end of the year it ended in.
- **Row menu.** Right-clicking a row (or the context-menu key on a focused one) opens a menu for that row alone: Muokkaa, Kopioi tosite, Jaa tosite, Merkitse maksetuksi and Poista tosite. A locked voucher (§8.11) hides Jaa and Poista, and so does a category that cannot be split (`canSplitLine`). Merkitse maksetuksi shows on open vouchers only and sets the payment date to the voucher's own date (`markEntryPaid`); it is refused when that year's Form 5 is filed, and the toast undoes it.

### 8.5 Entry dialog (Uusi tosite / Muokkaa tositetta / Kopioitu tosite)

A two-column modal. On mobile the columns stack.

- **Left column.** Date and type share a row, and so do the amount and the VAT %; both pairs fall back to one column below 560 px, where a date input and its picker no longer fit half a dialog.
  - Date.
  - Type as a segmented control (`EntryTypeToggle`: Tulo / Kulu, coloured green and red when selected).
  - Description (placeholder "Esim. Lasku 1006 – Asiakas Oy").
  - Category select: only enabled categories of the chosen type, plus the entry's current category even if disabled.
  - Amount, right-aligned with tabular figures. Every amount field in the app is an `AmountInput` (`components/common/amount-input.tsx`; `EuroInput` is the same with a euro sign), and each takes a sum as well as a number (`12,50*3`, `(45+30)/2`): `evalAmount` in `lib/domain/amount-expr.ts` reads `+ − * / x × ÷` and brackets with a hand-written parser, never `eval`, and a plain amount still goes through `parseAmount` with its rules. A pasted amount may carry `€`, `EUR`, `euro` or `euroa`, and `1.234.567` or `1,234,567` is read as thousands; `1,234` and `1.234` stay ambiguous, so the field offers "Tarkoititko: 1,23 € / 1 234,00 €" and never picks. A sum shows "= 37,50 €" under the field, and blur or `Enter` replaces the text with the result. Saving evaluates it too, so `Ctrl`/`⌘`+`Enter` works without leaving the field. A button beside "Verollisuus" flips gross and net and re-expresses the amount at the entry's rate (`calcEntry`), so the receipt total stays put, give or take the cent that §4 allows.
  - Every date field is a `DateInput` (`components/common/date-input.tsx`): typed text plus a calendar button. `parseDateInput` in `lib/domain/date-input.ts` reads `15.3.`, `15.3.26`, `15.3.2026`, `15032026`, `2026-03-15` and the words today, yesterday and tomorrow in Finnish, Swedish and English (`tänään`, `eilen`, `huomenna`). A date without a year takes the open year; words count from today. A date that does not exist (31.2.) marks the field invalid instead of rolling over. The value is ISO, so callers are unchanged.
  - VAT % select, hidden on an EU purchase category, where the amount takes the whole row (§6.9). Picking a category sets its default rate **as it was on the entry's date** (§5), and changing the date moves an unchosen rate across a rate change. A rate the user picked, one read from a PDF, and the rate of an entry being edited or copied count as chosen and stay. When the rate does not fit the date, a warning-coloured line under the field says so ("25,5 % on voimassa 1.9.2024 alkaen. Tälle päivälle verokanta on 24 %."). Saving is never blocked by it. A second warning line follows when the category's VAT cannot be deducted and the rate is above 0 %, saying to book the gross amount at 0 % (`vatNotDeductible`).
  - "Verollisuus" segmented control (Verollinen / Veroton).
  - A warning-coloured line under the amount when another entry has the same date, side and gross amount, naming its voucher number and description (`duplicateOf`). Attaching a file that another entry already holds raises a toast naming that entry (`entryWithReceipt`). Both are hints: two equal purchases on one day, or one receipt covering two entries, can be right.
  - An inline error line.
- **Footer:**
  - Edit mode: Poista, Kopioi, Peruuta, Tallenna.
  - New and copy modes: Peruuta, Tallenna ja uusi, Tallenna.
- **Right column:**
  - A **live receipt preview**, the signature visual element. It looks like a paper receipt with a perforated bottom edge and shows: type, date, description, category, net, VAT with rate, a bold total, and a badge ("Kasvattaa myynnin veroa" / "Vähennetään ostojen verona" / "Ei arvonlisäveroa").
  - Below it, the **"Liitteet" section:** a two-column grid (three on tablets) of 3:4 thumbnails. Images are shown cropped to the top; PDFs show their first page with a "PDF" badge. Each has a remove ✕. An "+ Lisää liite" tile and the hint "Kuva tai PDF. Voit myös raahata tiedoston tähän." follow. Clicking a thumbnail opens the viewer on that receipt.
  - **There is no name field.** The receipt's own file name is what names it in the archive (§7.2), so asking for a second name would only make the user type again what they already decided when they saved the file.
- **Defaults for a new entry:** if a month is selected, its date (today's day, capped at 28). Otherwise today if the year matches, else 1.1. of the selected year. The type and amount mode are the last ones used.
- **Validation:** a valid date, a non-zero amount and a chosen category are required. Error texts: "Anna päivämäärä.", "Anna summa, esim. 124,50.", "Valitse luokka." The error is held as `{ field, message }` where `field` is the `FormState` key: one `FieldError` line shows the message, and the field it names carries `aria-invalid` (the category select takes it through `OptionSelect`'s `invalid` prop). Editing that field clears the error, rather than leaving a complaint under a corrected value until the next save.
- **Pre-fill from a PDF:** adding an invoice PDF to an untouched form (no amount, no description) reads its text layer and fills the date, a description "Lasku {nro} – {myyjä} – {first row}" (whichever parts it found), the total as a gross amount and the VAT rate. A previous entry naming the same seller supplies the type and category; failing that, `suggestCategory` picks an expense category from words in the seller's name and the rows, falling back to 333. The seller is the company name printed beside a business ID, which is often only in the footer. A rate read this way survives picking a category. `lib/domain/invoice-text.ts` does the reading and is pure; `extractPdfText` in `lib/browser/pdf.ts` feeds it. The virtual barcode, when printed, wins over any labelled total or due date. A credit note keeps its minus, wherever it is printed, and its total is the largest amount by size. An amount like "2 123,00" reads as 2 123,00 €, since a quantity beside a price in the same text run cannot be told from a thousands separator. A scanned PDF has no text layer and pre-fills nothing; there is no OCR.
- **Nothing saves while a receipt is being stored:** "Tallenna" and "Tallenna ja uusi" are disabled and `Ctrl`/`⌘`+`Enter` waits, because the receipt is not in the form yet.
- **Toista joka kuukausi** keeps the entry as a monthly template (`lib/domain/recurring.ts`), in `settings.json` as `recurring`. Nothing books itself. When a month lacks a template's entry, the ledger shows a line for the selected month, or this month on the current year's whole-year view, and the overview's checklist has a row for this calendar month; both open a dialog that lists them, ticked, and adds them with an undo. **Whether a month has its entry is read from the entries, not stored**: the same side, category and description count, so a changed amount still counts, a deleted entry comes due again, and it survives the CSV. The date is the template's day, or the month's last day, and the rate follows it (§5). A template is monthly only. Unticking the box on an edited entry removes its template, and Asetukset, Toistuvat lists them with the amount and day editable.
- **Maksettu** offers the same day, another day with a date, or "Avoin", on any line that can be unpaid (§6.3). An open entry carries a pill in the ledger.
- **Kattaa ajanjakson** is two dates, the first and last day the entry covers, on any line that can be unpaid and only for a liikkeenharjoittaja (§6.3). Both or neither, the end not before the start. The hint names the small-item exemption of EVL 19 §.
- **The parts of a split share one payment.** A paid date, "Avoin" or the cash flag changed on one part is carried to the others (`sharePayment` in `lib/domain/split.ts`, run by the store's `upsertEntry` and `updateEntries`, so an edit undo carries it back too). Only a change travels, so editing another field never rewrites a sibling. A sibling on a line that cannot be unpaid, or one the move would take into a year whose Form 5 is filed (§8.11), is left alone. Deleting a part asks whether to delete only it or all parts (`choose` in `lib/ui/confirm.ts`, a confirm with a second button); one undo brings back whatever went. Bulk delete acts on the selected rows only. A file added to or removed from one part is added to or removed from the others (`shareReceipts`, the same hook), by the difference, so a file a sibling holds on its own stays. The shared file keeps its `id` and the ZIP stores it once (§7.2). Date and description stay per part. Editing a part keeps its `split`; copying one does not.
- **Jaa tosite** splits one receipt across categories or VAT rates (`DialogState` kind `split`, `components/entry/split-dialog.tsx`, `splitEntry` in `bulk-commands.ts`, `carveSplit` in `lib/domain/split.ts`). The footer of an edited, unlocked voucher offers it, except on an EU purchase and on a VAT payment, an owner's transfer or a loan, which have nothing to divide (`canSplitLine`). The dialog asks for the new part's amount in the voucher's own mode (gross or net), its category on the same side and its VAT rate. The original keeps what is left, so the parts always add up to the receipt, and the part must be smaller than the voucher and share its sign. The part is a voucher of its own with the next number, the same date, description, files and payment, and both carry one `split` id. A split is of the saved voucher, so unsaved edits are asked about first. It asks about a filed period like any change (§8.11) and the toast undoes it, unless the original was edited since. The ledger shows a "Jaettu 41, 42" pill with the numbers of every part. Nothing stores the receipt's total: it is the sum of the parts. A part's dialog says that the payment and the files are shared with the other parts, and offers **Yhdistä osa** (`mergeSplit`): it adds the part's amount to the sibling with the lowest voucher number, which keeps its category and rate, deletes the part, ends the split when only one part is left, asks first and can be undone from the toast. The change log records that a voucher became part of a split (`split` is a logged field, shown as "osa"), not the link's id.
- **Korjaa tositetta** (`Entry.reverses`, `lib/domain/reversal.ts`) links a refund, a credit note or a correction to the voucher it reverses. It is the last field of the Maksu tab, a searchable picker (`components/entry/voucher-picker.tsx`) of every other voucher in the book, any year, nearest in date first, each shown as number, date, description and gross amount. Every word typed must match somewhere in a row (number, description, date as shown or as ISO, amount), `Enter` picks the first match, and at most 50 rows are listed with a note on how many are left out. Vouchers that would close a loop are left out. The link is a note only: no figure, VAT return or check reads it, so the refund is still booked as its own row with its own amount and date. It is stored on the reversing entry alone, and the reversed one finds its reversals by looking, so the two ends cannot disagree and one voucher can have several. The ledger shows a "Korjaa 12" pill on the reversing row and a "Korjattu 20" pill on the reversed one, with the year added (`12/2025`) when the other end is in another year. The dialog of either end has a button that opens the other, after asking about unsaved edits. A copy does not keep the link. Deleting the target leaves the id in place, so an undo restores the link; it shows nowhere and the next save of the reversing entry drops it. The change log records that a link was added or removed ("linkitetty"), not the id. The CSV carries it in the `reverses` column (§7.1).
- **Maksettu käteisellä** (`Entry.cash`) sits under it on a paid entry. KPL 2:4 has cash payments booked "viipymättä" and day by day, so the check "Käteismaksu kirjattu myöhässä" flags a cash voucher added more than `CASH_BOOKING_DAYS` (2) days after its payment date. The law gives no number; two days allow a weekend. When it was added comes from the change log, so a voucher from a file whose log does not record adding it is not checked. A cash payment stays out of the bank estimate (§8.12). It is locked with the rest of a locked voucher.
- **Verokausi** appears under the category when it is a VAT payment or refund (§6.6), and the entry dialog can be opened with fields filled in (`DialogState.prefill`), which is how the VAT view books one.
- **Yksityisotto or Yksityissijoitus** as the category shows a line under it: neither income nor an expense, no effect on the result or VAT, and the bank statement as the receipt (`entry.ownerHint`, §6.7).
- **Koneiden ja kaluston hankinta or myynti** as the category shows a line under it: not an expense, the voucher feeds the depreciation base behind Form 5's 704, and the cost reaches the result as depreciation (`entry.assetHint`, §8.8). Account 1100 is the CSV's number; 704 is a Form 5 field.
- **Tallenna ja uusi** saves, keeps the date, resets the rest for the next entry, and puts the focus back on the date.
- **`Ctrl`/`⌘`+`Enter`** saves from any field: "Tallenna ja uusi" in the new and copy modes, where its button shows the key cap, and "Tallenna" when editing. It waits while a receipt is still being stored. A new or copied entry opens with the focus on the date, so a month's receipts can be entered from the keyboard alone.
- **Copy as new** (from a row or from the edit dialog): opens a new entry with every field copied **except receipts**. The date becomes today if the year matches, and the date field gets focus. The title is "Kopioitu tosite".
- Saving an entry from another year switches the selected year to that year.
- **Unsaved changes:** a snapshot of all fields (including receipt ids) is taken when the dialog opens. Closing with Peruuta or Escape while the snapshot differs asks "Hylätäänkö muutokset?" with the buttons "Jatka muokkausta" and "Hylkää muutokset". With no changes, it closes immediately.

### 8.6 Receipt viewer

A near full-screen modal.

- The top bar shows the file name and a sub-line ("Liite 1 / 2, 139 kt").
- Controls:
  - Previous/next receipt (when there are several).
  - Previous/next page with "Sivu 1 / 3" (PDFs with several pages).
  - Zoom out, a zoom percentage, and zoom in (1×–4×, steps of 1.5×).
  - Fit to view, rotate 90°, and save original. Closing is the dialog's own ✕ in the top right; the toolbar has no second one.
- The stage is a scrollable grey area. The content is drawn to a canvas: fitted to the stage at 100 %, sized for the device pixel ratio, with the image or PDF page rotated. Images never upscale beyond 100 % at fit. The view redraws on window resize.
- Keyboard: ←/→ moves between receipts, and +/− zooms.
- Missing files show "Tiedosto puuttuu" with the path. Undecodable images or PDFs show a message and a "save original" button.
- The content centres itself with `m-auto` rather than from the stage, so a zoomed receipt can be scrolled to all four edges. A new draw of a PDF cancels the one under way (`renderPdfPage`), since pdf.js refuses a second render on a canvas.

### 8.7 VAT return (ALV-laskelma)

- **The view opens on the period today falls in.** `vatIndex` is what the user has picked, null until then, so it cannot be a month number read as a quarter after a reload. `useVatPeriod` works out one index for the title, the figures and the filed mark.
- **The view has no period control of its own.** It always shows the filing period set in Settings (`vatPeriod`, §6.5, §8.10). A monthly or quarterly filer gets a strip of the year's months or quarters in the shape of the ledger's month chips (§8.4); a yearly filer gets the whole year and no strip. Figures by any other period are ones the user never files, so a second switch here would only duplicate the setting.
- Each chip shows where its period stands: Ilmoitettu, Myöhässä, the due date, Kesken, Tulossa, or "Ei ilmoitusta" for a period before the book's start (§6.5), whose banner says so instead of offering the return dialog. The result banner carries the way into it (`VatReturnButton`): "Ilmoita OmaVerossa" with the due date, or, once marked filed, the date it was marked with a label for what is left in the dialog: "Kirjaa maksu" or "Kirjaa palautus" while one is still to book, else "Näytä ilmoitus".
- **A period before the book's start is left out of the strip**, so a business founded in October is offered October to December rather than nine months that owe nothing. It stays out even when it holds entries, since a chip reading "Ei ilmoitusta" is no way to report a date on the wrong side of the start month. The one kept is the period on screen, so the strip always has a selected chip and the banner can explain it; it is reachable by having been selected before the start month was set.
- A result banner: "Maksettava arvonlisävero" (or "Palautettava…") as a large number, with the formula line "Myynnin vero X − ostojen vähennettävä vero Y".
- Two tables side by side, "Myynnin arvonlisävero" and "Ostojen vähennettävä vero", with the columns Verokanta, Veroton, Vero and Yhteensä, plus a totals row.
- A "Muut ilmoitettavat myynnit" panel, and a note explaining 0 % purchases and asking the user to check the figures before filing in OmaVero.

The view has two sub-pages, as tabs shaped like the settings tabs (`SubPageTabs`). `VatShell` holds the title, the tabs and the period strip. The routes are `VAT_ROUTES` in `lib/site.ts`.

- **Laskelma** at `/app/vat`: the banner, tables and panels above, and the way into the return dialog.
- **The return dialog** (`components/vat/vat-return-dialog.tsx`, `DialogState` kind `vat-return`) replaces the separate Ilmoitus page and is built like the year-end dialog (§8.8). It reports the period on screen, which `useVatPeriod` shares with the page. It has up to five steps, shown as a segmented control the user may move between freely:
  - **Tarkistukset.** `lib/domain/vat-checks.ts` (`vatCheckItems`, pure and tested) lists what stands between the period and its return, blockers first. The only blocker is a period that has not closed. Warnings are the entry checks of §8.4 (run over the whole year, then narrowed to the period's own entries, each with "Näytä"), unsaved changes, receipts missing from the file, and earlier closed periods not marked as filed. A period with no entries is information (a nil return). The wording of the entry checks is shared with the overview (`components/common/check-text.ts`).
  - **OmaVero.** Only in a book that has marked no return as filed, decided when the dialog opens. It sits after Tarkistukset and lists the five screens of a first return in OmaVero (sign in, start the return for the period, fill the fields, compare 308, send and keep the receipt), with a link to OmaVero. It has no state mark. The field-by-field part is Summat, which follows it.
  - **Summat.** The period's figures as the return's fields, on the `TaxForm` that Form 5 also uses, `embedded` (§8.8): the fields with an amount as a copy checklist, then the tax payable or refundable (308) to check against OmaVero. `lib/domain/vat-return.ts` maps the report to the fields.
  - **Merkintä.** The filed mark, which locks the period's vouchers (§8.11). "Merkitse ilmoitetuksi" is a footer button, disabled until the period has closed, as the year-end dialog's lock is (§8.8). The mark can be removed here.
  - **Maksu.** Only while there is a payment or refund to show or to book (§6.6): "Kirjaa maksu" or "Kirjaa palautus" opens the entry dialog filled in with today, the period's due, 0 %, the settlement category and the period. Booked entries are listed with their date and voucher number and "Avaa tosite", then whether they match the calculation. The button stays while there is a difference, for the rest of a part payment. An entry already booked shows on any period. Opening the entry dialog closes this one.
  - **A filed period opens on what is left.** With the filed mark set, the dialog opens on Maksu while a payment or refund is still to book (`useSettlementPending`), and on Merkintä otherwise. The other steps stay reachable, the checks among them. A green "Ilmoitettu {date}" chip sits beside the title on every step. Unfiled, the dialog opens on Tarkistukset.
  - **The filed mark takes a date.** Merkintä offers "Ilmoituspäivä" beside "Merkitse ilmoitetuksi", today by default and limited to the end of the period up to today. A filed period shows what has changed since: the fields whose amount differs from the figures kept with the mark (§6.5), or that the figures match. A change is an attention mark on the step, and the PDF lists it too (§8.21).
  - **Each step shows its state.** A check beside the step name when it is done (no blockers or warnings on Tarkistukset, the mark set, the payment booked) and a warning when it needs a look (open warnings, changes since filing).
  - **Maksutiedot.** On the Maksu step, while there is tax to pay, the tax account's IBAN and the reference number can be saved (`taxPayment`, in `settings.json`) and copied. They are the user's text; nothing sends or checks them.
  - **Maksu shows the due date** beside the unbooked payment, and says it has passed when today is later and the period still has no payment entry. A refund has no due date.
  - **"Lataa PDF"** in the footer downloads the period's return as a PDF (`vatReturnReport`, §8.21), on every step. It is the same document that Kirjaa maksu attaches to the voucher (§6.6).
  - **"Lataa Ilmoitin.fi-tiedosto"** in the footer downloads the closed period as the data file Ilmoitin.fi takes (`lib/domain/vat-file.ts`, specification VSRALVKV 1.10, saved as `docs/specs/verohallinto_tietuekuvaus_vsralvkv_290824.pdf`). The user uploads it themselves; the app sends nothing, and the form's other parts (corrections 332 to 335, the data of the EC Sales List) are not in it. One `code:value` line per field from `000:VSRALVKV` to `999:1`, CRLF line ends, amounts with a decimal comma. 014 is the business ID plus `_KP`, 048 is "Kirjanpito", 198 the time of making. 042 is the phone of "Yrityksen tiedot" and is left out when empty. Every amount field is written, zeros included, and 308 is negative for a refund. A period with no amounts is written as `056:1` with no amount fields, since check #1142 forbids both. The button is disabled, with the reason as its tooltip, while the period is still open, the business ID is missing, sales sit on the retired EU category (311 or 312 cannot be told apart), or 308 differs from the tax fields minus 307 (check #1924).
  - The names and order follow the return in OmaVero. The codes are those of Verohallinto's data file specification VSRALVKV (version 1.10), whose check #1924 the tests run: 308 is the tax fields minus 307. OmaVero is matched by name, so the intro says so.
  - 301 holds 25,5 % and 24 %, 302 holds 13,5 % and 14 %, 303 holds 10 %. 307 is all purchase VAT.
  - 309 (zero-rated turnover) is line 300 sales at 0 % plus non-EU sales. Its hint says to leave out exempt sales whose purchase VAT cannot be deducted, such as healthcare, because the book cannot tell them apart. 319 is reverse-charge sales.
  - 311 and 312 are the sales on `300-eu-goods` and `300-eu-services`. Their hints say these sales also go on the EC Sales List (yhteenvetoilmoitus). Sales on the retired `300-eu` (§5) get an extra "311/312" row, only while there are any.
  - EU purchases fill 305, 306, 313 and 314, and their deductible tax joins 307 (§6.9).
  - Imports fill 310 and 304 and domestic reverse-charge purchases fill 320 and 318 (§6.9). Their deductible tax is in 307.
  - A sales rate outside `RATES` has no field. It stays in 308 and the view warns about it.
  - With no amounts, the checklist points to "Ei toimintaa verokaudella".

- **Yhteenvetoilmoitus** at `/app/vat/ec`: the EC Sales List for the selected year, month by month, with each buyer's VAT number, goods and services (`lib/domain/ec-sales.ts`). It is monthly whatever the VAT period is, so the shell hides the period strip here. Due on the 20th of the next month or the next working day (vero.fi). The month is the entry's date, which stands in for the invoice's month on goods and the supply's or payment's on services. An EU sale gets "Ostajan ALV-numero" in the entry dialog, with a warning on a number of the wrong shape that never blocks saving. The app has no connection to VIES. A sale with no number is listed for the user to fix.
- **The reminder banner** (`components/app/vat-reminder-banner.tsx`, rule in `lib/domain/vat-reminder.ts`) sits under the top bar on every page. It shows for the oldest overdue return, else for the first closed, unfiled one that falls due within seven days (`VAT_REMINDER_DAYS`), on the due date that already moved past weekends and holidays (§6.5). It names the period, the due date and the days left, and "Avaa ilmoitus" selects that period and opens the return dialog. An overdue banner is red and has no day count. "Piilota" hides it until the page is reloaded. It never shows for an open or filed period, for a book that has not begun, or while an archive is open. It reminds only while the app is open: a static page cannot push anything, and the calendar export (§8.22) is the reminder outside the app. `lib/domain/vat-reminder.test.ts` covers the rule.

### 8.8 Income statement (Tuloslaskelma)

Presented as a printable **sheet**: the `--sheet` surface (warm paper in light, the card tone in dark — see §11), a thin border, and a soft shadow. It has the title, the period, sections with totals, greyed group headings, lines with muted account numbers, and a double-ruled result line. A "Tulosta" button calls `window.print()`, and the print styles hide the chrome: `.print-hidden`, which the top bar carries, and the sidebar by its `data-slot`.

Every view prints through the browser's print dialog, which also saves a PDF. `PrintButton` (`components/common/print-button.tsx`) is the one button, and `PageHeader` hides its actions on paper, so a view that prints keeps its title and period. The VAT return (`Laskelma`) and the summary print as they are. The ledger prints every row its filters leave, not the page on screen: the button renders them all, then calls `window.print()`. The checkbox and action columns drop out, and the type, net, VAT and category columns show whatever the screen width. Tables stop scrolling on paper (`globals.css`).

The view has four sub-pages, as tabs shaped like the settings tabs (§8.10, `SubPageTabs` in `components/common/sub-page-tabs.tsx`). `StatementShell` holds the title, "Tulosta" and the tabs, so every page prints. The routes are `STATEMENT_ROUTES` in `lib/site.ts`.

- **Laskelma** at `/app/statement`: the sheet above, the year's VAT by filing period under it (`VatYearSection`, `vatYear` in `lib/domain/vat-year.ts`: the tax, the deductible tax (307), the tax payable or refundable (308), the filed mark or due date, and a year total; periods are skipped as in the retention package, §8.21; nothing is shown when no period has a voucher on the return), and the way into the year-end dialog.
- **The year-end dialog** (`components/statement/year-end-dialog.tsx`, `DialogState` kind `year-end`) replaces the separate Lomake 5 page. "Ilmoita OmaVerossa" in the sheet's heading (`YearEndButton`, hidden on paper) opens it for the selected year. It has four steps, shown as a segmented control the user may move between freely:
  - **Tarkistukset.** `lib/domain/year-end.ts` (`yearEndItems`, pure and tested) lists what stands between the year and its return, blockers first. The only blocker is a year that has not ended. Warnings are the entry checks of §8.4 (each with "Näytä", which closes the dialog and opens the ledger on them), unsaved changes, receipts missing from the file, closed VAT periods of the year not marked as filed, a depreciation allowance left unused (the register of Poistot, with the maximum), and private use of a car on 313. OmaVero works 313 out from the driving details (271, 273, 381, 396, specification check #1882), which the book does not hold, so the warning says to enter them there and check that 313 matches. Information rows are a year with no entries, year-end figures never typed in on Varat ja velat, vouchers still open at 31.12., and empty months. With nothing to flag it says the year is ready. The wording of the entry checks is shared with the overview (`components/common/check-text.ts`).
  - **Summat.** The same figures as Form 5's fields, in the form's order, with its codes and labels (`lib/domain/form5.ts`), followed by the assets, liabilities and wages of `lib/domain/form5-balance.ts`, so one checklist covers everything the app fills. `useForm5` builds the sections and `TaxForm` renders them with `embedded`, which drops its own surface, title and footer. ### 8.11 Confirmations and unsaved-change rules (apply everywhere)

Use one shared `AlertDialog`-based `confirm()` helper, with a title, a message, a destructive confirm button (red) and a cancel button. The cancel button can be relabelled, e.g. "Jatka muokkausta", and gets focus by default.

`alertDialog()` is the same primitive with no cancel label: one button, nothing to decide. It is for the cases where **nothing happened and the reason is the whole message** — a file the app could not open (§7.1). A toast is easy to miss and carries two sentences badly; a partial problem, where the book did open, stays a toast. Never `window.alert` (§2).

Cases:

| Trigger                                | Condition                          | Title / confirm label                                                     |
| -------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------- |
| Close file ("Sulje tiedosto")          | unsaved changes                    | "Suljetaanko tiedosto?" / "Sulje tallentamatta"                           |
| Start new bookkeeping                  | unsaved changes                    | same as above                                                             |
| Open a file over the current one       | unsaved changes                    | "Korvataanko avoin kirjanpito?" / "Korvaa"                                |
| Save over a file edited elsewhere      | its timestamp moved since we read it | "Korvataanko tiedosto?" / "Korvaa"                                      |
| Delete an entry (row or dialog)        | not in a locked period             | "Poistetaanko tosite?" / "Poista" |
| Save an entry                          | it adds to a period marked as filed | "Muutetaanko ilmoitettua kautta?" / "Tallenna silti"                     |
| Delete the whole bookkeeping           | always                             | "Poistetaanko kirjanpito?" / "Poista kirjanpito"                         |
| Close the entry dialog (Peruuta / Esc) | form differs from its snapshot     | "Hylätäänkö muutokset?" / "Hylkää muutokset", cancel = "Jatka muokkausta" |
| Browser tab close (`beforeunload`)     | any of the above dirty states      | the browser's native prompt                                               |

**Dirty bookkeeping** means the entries or the book's settings changed since the last read or write of a file. It is set by any add, edit or delete, by a category change, and by the VAT period, a filed mark, an archived year or the overview layout (§7.6), and cleared by opening a file, by saving to the linked one, and by downloading a ZIP **only when no file is linked** (§7.5). A book with no entries asks too: deleting the last one still left the file behind.

The wording everywhere is about saving rather than exporting, so one set of strings covers both ways of keeping the work. The row above that highlights this: the close confirmation is the same sentence whether the user saves to their own file or downloads a copy.

Closing a file clears entries, the file name and filters, puts the categories back to the defaults, unlinks the file (§7.5), sets the bookkeeping to closed, garbage-collects receipts, and returns to the landing page. A new bookkeeping starts from the default categories too: custom ones and changed rates belong to the old file (§7.6).

**A filed period and a stored year are locked** (`lib/domain/period-lock.ts`). KPL 2:7 forbids changing or deleting the content of a voucher or a book after a periodic return has been made from it, or after the financial statements are prepared. So an entry the VAT return counts (`countsOnVatReturn`, the rule `vatReport` itself uses), dated in a period marked as filed, opens read-only, with "Lukittu" beside the dialog's title and the reason in a popover that opens on hover or tap. So does every entry of a year whose Form 5 is marked as filed (`form5Filed`, set in the year-end dialog, §8.8) or which is marked as stored. Form 5 reads an entry by the year it was paid (§6.3), so an entry paid in a filed Form 5 year is locked too, whatever year it is dated in (`form5Paid`): a prepayment, paid before its date. No new entry can be paid in such a year either. An entry the VAT return does not count, such as YEL, a bank fee, a grant, an owner's transfer, a loan or a VAT payment, stays open after a VAT return until Form 5, and changing it so that the return would count it gets the warning below. Delete, bulk actions, clearing and renumbering refuse with a toast (`refuseLocked`). The payment date stays open, since a later payment adds to what is known and alters nothing reported, but a Form 5 year is stricter: no payment date may be set in it or moved out of it (`paidChangeHitsForm5`), since its year-end receivables and an ammatinharjoittaja's result follow those dates. "Tee korjaustosite" opens a new entry with the opposite amount, dated today. Removing the mark unlocks the entry, which is how a mark made by mistake gets undone, and the log shows it. No new entry can be dated in a stored year or a year whose Form 5 is filed. The year-end figures on Varat ja velat lock with Form 5 too. **Not locked:** the asset opening balance, which can still change a filed year's figures.

**Every change to the entries is logged** (`lib/domain/change-log.ts`). The store's entry actions diff the entries before and after and append one record per voucher: added, edited with each field's old and new value (a new voucher number included), deleted or restored. An undo is logged as its own record. Each mark set or removed is logged too, and a file opened with no log, such as a plain CSV, starts one with a record saying so. The log is `changeLog` in `settings.json` and the browser's blob. **The app shows it only on the voucher**: `EntryHistory` lists an entry's records, in a closed section of its dialog (`EntryDisclosure`), once anything beyond adding it has happened. A deleted voucher has no dialog, so its record, and the records of the marks, stay in `settings.json` with no view in the app. **Opening a file relinks the log** (`relinkChangeLog`): the CSV has no id column, so entries take new ids, and each old id's newest record gives the voucher number and year that find its entry again. A record of a deleted voucher, or of one renumbered outside the app, keeps its old id. **`parseSettings` rebuilds every record field by field**, since the dialog renders what it holds; an action this version does not know is kept, so saving a newer file does not cut its log. **It records use of the app.** A file the user controls can be edited by hand, so the log is not proof, and the landing page's FAQ says so.

**A change that adds to a filed return says how to correct it.** `filedPeriodChanges` in `lib/domain/filed-changes.ts` builds each touched period's return before and after the change and compares the fields, so an entry no field counts (a 0 % grant) asks nothing. For each period that does change, the confirmation names it, the date it was marked, and how much the tax payable goes up or down. It then gives Vero's fix (vero.fi, "Miten arvonlisäveroilmoituksen tietoja korjataan?"): a replacement return (korvaava ilmoitus) for the period in OmaVero, or, when only the tax fields change and by at most 500 €, the next return instead (`fitsNextReturn`). A change to EU, reverse-charge or 0 % sales always needs the replacement. The filed mark stays as it was, since the user decides when the correction is made. `lib/commands/filed-commands.ts` holds the wording and is loaded on demand by `deleteEntry`, because `book-commands.ts` is in the landing bundle.

**Deleting can be undone.** Deleting an entry still asks first, then raises a toast with "Kumoa" for 10 seconds (`offerUndo` in `lib/commands/book-commands.ts`). An undo also brings back a custom category deleted in the meantime, and undoing a bulk category change only moves the category back, so an edit made since stays. The deleted entries' receipts stay in IndexedDB while the toast is up (`undoAttachmentIds`, which the GC sweep counts as live), or an undo would bring back entries whose files were already gone. An undo after a new, closed or opened bookkeeping has taken over does nothing (`bookEpoch`). Undo marks the book dirty, since autosave may already have written the deletion. `lib/commands/book-commands.test.ts` covers it.

**Editing one voucher can be undone too.** Saving an edited entry in the dialog raises "Muutokset tallennettu" with "Kumoa" for 10 seconds (`offerEditUndo`). The undo puts the whole entry back as it was: its fields, its receipts, its voucher number (also after a move to another year) and the monthly template the edit changed or made. Receipts the edit removed stay in IndexedDB while the toast is up, like a delete's. The undo does nothing once another bookkeeping has taken over, and it refuses with a message when the entry has been edited again since or is locked (§8.11). Bulk edits (§8.4) have their own undo and are not part of this.
